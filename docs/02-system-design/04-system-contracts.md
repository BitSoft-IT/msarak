# المرحلة السابعة — عقود النظام والطلبات والاستجابات

**الملف:** `09-system-contracts.md`  
**الحالة:** معتمدة للتنفيذ  
**آخر تحديث:** 2026-09-11  
**النطاق:** Routes، الصلاحيات، المدخلات، الاستجابات، والأخطاء.  
**خارج النطاق:** كتابة Controllers، تصميم الشاشات، وOpenAPI عامة.

---

## 1. القرار الحاكم

النظام تطبيق Laravel واحد يستخدم:

- **Blade/HTML** لصفحات العرض.
- **Fetch + JSON** لحفظ الإجابات والإكمال وعمليات المدير.
- **Session Authentication** باستخدام إمكانات Laravel الأساسية دون Starter Kit.
- **CSRF** لكل طلب يغير البيانات.
- المسارات في `routes/web.php`، دون `/api` أو Sanctum.

لا توجد API عامة في النسخة الأولى. إذا ظهر تطبيق جوال أو تكامل خارجي لاحقًا، يصمم له `/api/v1` مستقل.

## 2. قواعد العقود

### صفحات HTML

- تعيد `200` عند النجاح.
- تعيد Redirect بعد التسجيل والدخول والنماذج التقليدية.
- تعرض صفحة `404` أو `403` المناسبة دون تفاصيل داخلية.

### طلبات Fetch

ترسل:

```http
Accept: application/json
Content-Type: application/json
X-CSRF-TOKEN: <token>
```

استجابة النجاح:

```json
{
  "data": {},
  "message": "تمت العملية بنجاح."
}
```

استجابة الخطأ:

```json
{
  "message": "تعذر تنفيذ العملية.",
  "code": "ERROR_CODE",
  "errors": {
    "field": ["رسالة تحقق واضحة."]
  }
}
```

- `errors` يظهر فقط عند أخطاء الحقول.
- الرسائل للمستخدم بالعربية الواضحة.
- `code` ثابت ليستفيد منه JavaScript والاختبارات.

## 6. عقد بدء التقييم

### الطلب

POST /assessment/sessions

لا يحتاج الطلب إلى Body.

يعتمد الخادم على جلسة Laravel الحالية لتحديد الطالب المسجل، ولا تستخدم API Tokens أو Sanctum أو JWT.

يحدد الخادم إصدار التقييم المنشور الصالح باستخدام `PublishedAssessmentService`.

### الاستجابة عند إنشاء جلسة جديدة

الحالة:

201 Created

{
  "data": {
    "session_id": 42,
    "status": "in_progress",
    "assessment_version_id": 3,
    "resumed": false,
    "redirect_url": "/assessment/sessions/42"
  },
  "message": "بدأ التقييم."
}

### الاستجابة عند استئناف جلسة غير مكتملة موجودة

الحالة:

200 OK

{
  "data": {
    "session_id": 42,
    "status": "in_progress",
    "assessment_version_id": 3,
    "resumed": true,
    "redirect_url": "/assessment/sessions/42"
  },
  "message": "تم استئناف التقييم."
}

### القواعد

- يجب أن يكون المستخدم مسجل الدخول وتحت صلاحية الطالب.
- لا يرسل المتصفح معرف المستخدم أو معرف إصدار التقييم.
- يحدد الخادم الطالب من Session Authentication.
- يحدد الخادم الإصدار المنشور الصالح باستخدام `PublishedAssessmentService`.
- إن وجدت جلسة `in_progress` للطالب مرتبطة بالإصدار المنشور نفسه، تعاد الجلسة نفسها بدل إنشاء جلسة مكررة.
- إن لم توجد جلسة غير مكتملة، تنشأ جلسة جديدة بحالة `in_progress`.
- تكرار طلب البدء لا ينشئ أكثر من جلسة غير مكتملة لنفس الطالب والإصدار.
- لا ترسل رموز RIASEC أو الأوزان أو منطق الحساب إلى المتصفح.

### عدم توفر تقييم منشور

إذا لم يوجد إصدار منشور صالح، أو كانت حالة الإصدار المنشور غير صالحة للاستخدام، يستخدم النظام الخطأ المعتمد من `AssessmentUnavailableException`.

الحالة:

409 Conflict

{
  "message": "لا يتوفر اختبار التقييم حالياً. برجاء المحاولة لاحقاً.",
  "code": "ASSESSMENT_UNAVAILABLE"
}

الرمز `ASSESSMENT_UNAVAILABLE` ثابت ويطابق التنفيذ الحالي في `AssessmentUnavailableException`.

{

  "position": 7,

هذه البنية تطابق البيانات الآمنة التي يوفرها `PublishedAssessmentService`.

- `riasec_code`.
- أوزان الخيارات.
- قواعد حساب RIASEC.

### حالات الجلسة المعتمدة

الحالات المستخدمة بين Backend وFrontend في النسخة الحالية هي فقط:

| الحالة | المعنى |
|---|---|
| `in_progress` | الجلسة قابلة للاستئناف وتعديل الإجابات. |
| `completed` | التقييم مكتمل ولا تقبل إجابات جديدة أو تعديلات. |

لا تضاف حالة جديدة دون حاجة موثقة وتحديث هذا العقد قبل التنفيذ.


## 8. عقد حفظ الإجابة

### المسار

PUT /assessment/sessions/{assessmentSession}/answers/{question}

يعمل المسار تحت `auth` و`role:student`.

### الحالة الأولى — اختيار أساسي

{
  "primary_option_id": 25,
  "none_selected": false,
  "unable_to_judge": false,
  "ratings": [
    {
      "option_id": 25,
      "rating": 2
    },
    {
      "option_id": 26,
      "rating": 1
    }
  ]
}

### الحالة الثانية — لا ينطبق أي خيار

{
  "primary_option_id": null,
  "none_selected": true,
  "unable_to_judge": false,
  "ratings": []
}

`ratings` اختيارية ويمكن أن تكون غائبة أو فارغة.

### الحالة الثالثة — تعذر الحكم

{
  "primary_option_id": null,
  "none_selected": false,
  "unable_to_judge": true,
  "ratings": []
}

عند `unable_to_judge=true` يمنع إرسال `primary_option_id` أو أي عناصر داخل `ratings`.

### سلم التقييم الاختياري

عند تقييم أحد الخيارات السلوكية، تستخدم الواجهة القيم التالية:

| الوصف المعروض | القيمة |
|---|---:|
| يشبهني جدًا | `2` |
| يشبهني | `1` |
| محايد / غير متأكد | `0` |
| لا يشبهني | `-1` |
| لا يشبهني إطلاقًا | `-2` |

قواعد ملزمة:

- التقييم اختياري ولا يشترط تقييم جميع الخيارات.
- غياب تقييم لخيار يختلف عن `rating = 0`.
- عدم وجود تقييم يعني أن الطالب لم يقيّم الخيار.
- `rating = 0` يعني أن الطالب اختار صراحةً «محايد / غير متأكد».
- هذه القيم تخص `ratings` فقط ولا تغير `primary_option_id`.
- لا ترسل رموز RIASEC أو أي أوزان حسابية إلى المتصفح.
- 

### قواعد التحقق

- يجب اختيار حالة واحدة بالضبط من:
  - `primary_option_id` يحتوي معرف خيار.
  - `none_selected=true`.
  - `unable_to_judge=true`.
- لا يجوز الجمع بين أكثر من حالة.
- `primary_option_id`، عند وجوده، يجب أن ينتمي إلى السؤال المطلوب.
- السؤال يجب أن ينتمي إلى إصدار جلسة التقييم.
- `ratings` اختيارية ويمكن أن تكون فارغة.
- كل عنصر داخل `ratings` يحتوي:
  - `option_id`.
  - `rating`.
- كل `option_id` داخل `ratings` يجب أن ينتمي إلى السؤال نفسه.
- كل `rating` يجب أن يكون عددًا صحيحًا ضمن `-2..2`.
- لا يجوز تكرار `option_id` داخل `ratings` في الطلب نفسه.
- عند `unable_to_judge=true` يجب ألا توجد تقييمات.
- الجلسة يجب أن تكون مملوكة للطالب.
- الجلسة يجب أن تكون بحالة `in_progress`.

حقول العقد الخارجية:

`none_selected`

و:

`unable_to_judge`

هي جزء من عقد التكامل بين الواجهة والخادم فقط، ولا تغير بنية قاعدة البيانات.

يقوم تنفيذ B-03 لاحقًا بترجمتها إلى `response_type` الداخلي المناسب دون تغيير قاعدة البيانات.

### نجاح الحفظ — 200

{
  "data": {
    "question_id": 7,
    "saved": true,
    "answer": {
      "primary_option_id": 25,
      "none_selected": false,
      "unable_to_judge": false,
      "ratings": [
        {
          "option_id": 25,
          "rating": 2
        },
        {
          "option_id": 26,
          "rating": 1
        }
      ]
    },
    "progress": {
      "processed": 7,
      "total": 18
    }
  },
  "message": "حُفظت الإجابة."
}

### تعديل إجابة موجودة

إذا كانت الإجابة موجودة مسبقًا للسؤال نفسه داخل الجلسة، يحدث الخادم الإجابة نفسها ويعيد:

200 OK

ولا ينشئ Answer جديدًا لنفس السؤال داخل الجلسة.

### الطلب المكرر

إعادة نفس الطلب بالقيم نفسها تعيد:

200 OK

ولا تنشئ إجابة أو تقييمات مكررة.

### خطأ التحقق — 422

يستخدم عند مخالفة قواعد التحقق السابقة، مثل:

- اختيار أكثر من حالة.
- خيار لا يتبع السؤال.
- تقييم خارج `-2..2`.
- تكرار نفس الخيار داخل `ratings`.
- إرسال تقييمات مع `unable_to_judge=true`.

شكل الاستجابة:

{
  "message": "بيانات الإجابة غير صالحة.",
  "code": "ANSWER_INVALID",
  "errors": {
    "primary_option_id": [
      "الاختيار غير صالح لهذا السؤال."
    ]
  }
}

### جلسة غير مملوكة — 404

{
  "message": "المورد غير موجود.",
  "code": "RESOURCE_NOT_FOUND"
}

لا تكشف الاستجابة أن الجلسة موجودة أو مملوكة لطالب آخر.

### محاولة تعديل جلسة مكتملة — 409

{
  "message": "لا يمكن تعديل إجابات جلسة مكتملة.",
  "code": "SESSION_COMPLETED"
}

### فشل الحفظ الداخلي — 500

{
  "message": "تعذر حفظ الإجابة. حاول مرة أخرى.",
  "code": "ANSWER_SAVE_FAILED"
}

لا ترسل SQL أو Stack Trace أو تفاصيل داخلية إلى المتصفح.

هذا العقد يخص تعريف السؤال داخل بنك التقييم، وليس شكل الاستجابة الكامل الذي يراه الطالب أثناء تنفيذ التقييم.

### الإنشاء أو الاستبدال

{
  "position": 7,
  "scenario": "نص الموقف",
  "options": [
    {
      "position": 1,
      "text": "نص الخيار الأول",
      "riasec_code": "I"
    },
    {
      "position": 2,
      "text": "نص الخيار الثاني",
      "riasec_code": "S"
    },
    {
      "position": 3,
      "text": "نص الخيار الثالث",
      "riasec_code": "E"
    },
    {
      "position": 4,
      "text": "نص الخيار الرابع",
      "riasec_code": "C"
    }
  ]
}

### معنى الخيارات الأربعة

- `options` تحتوي أربعة خيارات سلوكية فقط.
- كل خيار يمثل مجالًا واحدًا من RIASEC.
- هذه الخيارات هي التي تخزن في جدول `question_options`.
- كل خيار يملك `riasec_code` داخليًا.
- لا ترسل قيمة `riasec_code` إلى واجهة الطالب.

### خيارات الاستجابة غير المخزنة داخل `question_options`

يوجد خياران إضافيان في رحلة الطالب، لكنهما لا يعدان من خيارات السؤال الأربعة ولا يخزنان كسجلات داخل `question_options`:

1. `none_selected`

   المعنى المعروض للطالب:

   `لا يشبهني أي من هذه التصرفات`

   ويمثل داخليًا:

   `response_type = none`

   و:

   `primary_option_id = NULL`

2. `unable_to_judge`

   المعنى المعروض للطالب:

   `لا أستطيع الحكم على هذا الموقف`

   ويمثل داخليًا:

   `response_type = cannot_judge`

   و:

   `primary_option_id = NULL`

هذان الخياران جزء من عقد استجابة الطالب في `## 8. عقد حفظ الإجابة`، وليس من عقد إنشاء أو تعديل بنك الأسئلة.

### التحقق

- الإصدار `draft` فقط.
- الموضع من 1 إلى 18 وفريد داخل الإصدار.
- السيناريو غير فارغ.
- أربعة خيارات سلوكية بالضبط داخل `options`.
- مواضع الخيارات من 1 إلى 4 وفريدة.
- كل `riasec_code` من القيم `R`, `I`, `A`, `S`, `E`, `C`.
- لا يتكرر مجال RIASEC داخل السؤال نفسه.
- لا تخزن `none_selected` أو `unable_to_judge` داخل `question_options`.
- لا تخزن أوزان ثابتة داخل `question_options`.
- قيم التقييم الاختيارية `-2..2` تخص إجابة الطالب وتخزن ضمن `answer_option_ratings`، وليست جزءًا من تعريف خيار السؤال.

استبدال السؤال يستبدل خياراته الأربعة داخل Transaction واحدة.

## 14. عقد نشر الإصدار

### الطلب

```http
POST /admin/assessment-versions/{version}/publish
```

لا يحتاج Body.

### شروط النشر

- الحالة `draft`.
- 18 سؤالًا بمواضع 1–18.
- أربعة خيارات لكل سؤال.
- 72 خيارًا.
- كل مجال RIASEC يظهر 12 مرة.
- الأوزان مطابقة للنموذج المعتمد.

### الاستجابة

```json
{
  "data": {
    "id": 4,
    "version_number": 4,
    "status": "active",
    "published_at": "2026-09-02T11:00:00Z"
  },
  "message": "نُشر إصدار التقييم."
}
```

النشر المتكرر للإصدار النشط يعيد حالته مع `200`، ولا ينشئ إصدارًا جديدًا.

## 16. حالات HTTP والأخطاء

| الحالة | الاستخدام |
|---:|---|
| 200 | قراءة، تحديث، استئناف، أو تكرار عملية مكتملة |
| 201 | إنشاء جلسة أو مسودة أو سؤال أو نتيجة لأول مرة |
| 204 | حذف ناجح دون محتوى |
| 401 | غير مسجل في طلب JSON |
| 403 | الدور لا يملك الوظيفة |
| 404 | المورد غير موجود أو لا يملكه المستخدم |
| 409 | تعارض حالة: مكتمل، غير متاح، أو غير قابل للتعديل |
| 422 | مدخلات غير صالحة أو نموذج غير جاهز للنشر |
| 429 | تجاوز حد المحاولات |
| 500 | خطأ داخلي برسالة عامة |

رموز التطبيق:

| HTTP | الرمز | الاستخدام |
|---:|---|---|
| `409` | `ASSESSMENT_UNAVAILABLE` | لا يوجد إصدار تقييم منشور صالح يمكن بدء التقييم منه. |
| `409` | `SESSION_COMPLETED` | محاولة حفظ أو تعديل إجابة بعد اكتمال الجلسة. |
| `409` | `SESSION_NOT_READY` | لم تتحقق شروط إكمال التقييم. |
| `422` | `ANSWER_INVALID` | بيانات الإجابة تخالف قواعد التحقق المعتمدة، مثل حالة إجابة غير صالحة، خيار لا يتبع السؤال، تقييم خارج `-2..2`، أو تكرار خيار داخل `ratings`. |
| `500` | `ANSWER_SAVE_FAILED` | تعذر حفظ الإجابة بسبب خطأ داخلي غير متوقع، دون كشف تفاصيل تقنية للمتصفح. |
| `409` | `VERSION_NOT_DRAFT` | محاولة تعديل إصدار تقييم غير قابل للتعديل. |
| `422` | `VERSION_NOT_PUBLISHABLE` | إصدار التقييم لا يحقق شروط النشر. |
| `403` | `FORBIDDEN` | المستخدم مسجل لكنه لا يملك الدور المطلوب للعملية. |
| `404` | `RESOURCE_NOT_FOUND` | المورد غير موجود أو لا يملكه المستخدم؛ ويستخدم خصوصًا لإخفاء وجود جلسة تخص طالبًا آخر. |

قواعد رحلة التقييم الملزمة:

- مخالفات التحقق في عقد حفظ الإجابة تعيد `422 ANSWER_INVALID`.
- الوصول إلى جلسة لا يملكها الطالب يعيد `404 RESOURCE_NOT_FOUND` ولا يكشف وجودها.
- محاولة تعديل إجابة في جلسة `completed` تعيد `409 SESSION_COMPLETED`.
- عدم توفر إصدار تقييم منشور صالح يعيد `409 ASSESSMENT_UNAVAILABLE`.
- الأخطاء الداخلية غير المتوقعة في الحفظ تعيد `500 ANSWER_SAVE_FAILED` برسالة عامة فقط.
- لا ترسل أي استجابة SQL أو Stack Trace أو أسماء جداول أو تفاصيل داخلية إلى المتصفح.

## 17. الصلاحيات والملكية

| المورد | الطالب | المدير |
|---|---|---|
| دليل التخصصات | قراءة | قراءة |
| جلسة الطالب | المالك فقط | لا وصول تشغيلي |

- التحقق يتم في Policies/Services، لا في JavaScript.
