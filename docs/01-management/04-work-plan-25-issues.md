- الخطة تحتوي على 25 مهمة رئيسية: خمس لكل عضو.

## 10. شرط بدء أي Issue — Definition of Ready

- الهدف والناتج واضحان.
- المسؤول والمراجع محددان.
- الاعتماديات `Done`.
- معايير القبول مكتوبة.
- العقد أو القرار التقني المرتبط معتمد.
- الملفات المتوقعة معروفة.
- لا يوجد تعارض مفتوح يمنع التنفيذ.

## 11. شرط إغلاق أي Issue — Definition of Done

- المطلوب منفذ دون توسع خارج النطاق.
- الاختبارات المطلوبة ناجحة.
- التوثيق المتأثر محدث.
- أضيف `docs/commands/<issue-code>.md` عند استخدام أوامر تنفيذ مهمة.
- فحص Pull Request من المراجع المحدد (Approve خارجي، أو Self-review موثقة عند تطابقه مع المنفذ).
- عولجت الملاحظات الإلزامية.
- نجح CI.
- دُمج التغيير في `main` وأغلقـت Issue وحُذف الفرع.

## 12. قواعد تغيير الخطة

- لا يضاف عمل كبير إلى Issue جارية؛ تنشأ Issue جديدة.
- لا يغير عضو اعتمادًا أو معيار قبول دون توضيح السبب.
- عند تأخر اعتماد، ينتقل العضو إلى مهمة مستقلة جاهزة إن وجدت.
- لا تنقل ملكية Issue إلا بقرار واضح من الحارث داخل GitHub.
- أي تغيير في المتطلبات أو المعمارية يحدث الوثائق والـIssues المتأثرة معًا.

## 13. الخطوة التالية بعد الاعتماد

بعد اعتماد هذا الملف يُكتب دليل GitHub النهائي، ثم تُجهز قوالب Issue وPull Request وCode Review. بعد ذلك فقط يُنشأ المستودع واللوحة والـ25 Issue فعليًا.
