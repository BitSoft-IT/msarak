# حوكمة الهندسة البرمجية الخفيفة

**المشروع:** مسارك
**الحالة:** معتمدة للتطبيق على الدفعات المتبقية
**آخر تحديث:** 2026-09-21

## مصدر الحقيقة

عند التعارض يعتمد الترتيب التالي:

1. Decision Log عند وجود قرار أحدث معتمد.
2. المواصفة المتخصصة الأحدث:
   - question_bank_specification.md لنموذج التقييم والحساب.
   - 04-system-contracts.md لعقود Frontend/Backend.
3. القرارات التقنية والمعمارية المعتمدة.
4. Issue التنفيذ الحالية لنطاق المهمة.
5. الكود على main هو التنفيذ المدموج، لكنه لا يشرعن مخالفة قرار أعلى.

إذا خالف الكود المصدر المعتمد فذلك Defect أو Change يحتاج معالجة.

## منع التعليمات القديمة

عند استبدال قرار:
- تحدث الوثيقة المتأثرة.
- يحذف النص القديم أو يعلّم بوضوح بأنه Superseded.
- لا يجوز تنفيذ تعليمات ثبت أنها مستبدلة.
- التعارض غير المحسوم يمنع الجزء المتعارض فقط من التنفيذ.

## Definition of Ready

تكون المهمة Ready عندما:
- الهدف واضح.
- الاعتماديات جاهزة.
- Acceptance Criteria قابلة للتحقق.
- العقد واضح عند وجود تكامل.
- لا يوجد قرار مفتوح يمنع التنفيذ.
- المراجع معروف.
- مصدر الحقيقة محدد.

## Definition of Done

تكون المهمة Done عندما:
- تحقق نطاقها ومعايير قبولها.
- تنجح الفحوص والاختبارات المطلوبة.
- تحدث الوثائق المتأثرة.
- لا تبقى تعليمات قديمة متعارضة.
- لا توجد أسرار أو Debug artifacts.
- PR مراجع.
- CI ناجح.
- التغيير مدموج في main.

## Change Management

Change Request مطلوب فقط إذا تغير:
- Scope/MVP
- Data Model
- عقد مشترك
- Scoring/Recommendation
- Security/Auth
- قرار معماري
- سلوك تعتمد عليه عدة مهام

لا يحتاج CR:
- Typo
- تحسين صياغة
- Refactor لا يغير السلوك
- Bug fix يعيد النظام للمواصفة الحالية

المسار:

Propose
→ Impact Review
→ Decision
→ Update Source of Truth
→ Update affected Issues
→ Implement
→ Verify

## قاعدة الخفة

لا اجتماعات إلزامية ولا مستند لكل تعديل صغير ولا طبقة موافقات جديدة.
تستخدم الحوكمة فقط عندما تمنع خطأ أو توضح قرارًا حقيقيًا.
