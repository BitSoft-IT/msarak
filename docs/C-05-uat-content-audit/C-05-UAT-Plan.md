# C-05 — خطة اختبار قبول المستخدم وتدقيق المحتوى

**المشروع:** مسارك — منصة التوجيه الأكاديمي والمهني لطلاب المرحلة الثانوية في اليمن
**المهمة:** C-05 — UAT والتوثيق وتدقيق المحتوى النهائي
**الإصدار:** 1.0
**الحالة:** Stage A — خطة أولية جاهزة للمراجعة
**المراجع الأساسي:** `Abdullah-Al-basheri`
**مراجع عند الحاجة:** `ayman-albaidahi` لمطابقة الواجهة، و`Alhareith` لجاهزية الإصدار

## 1. الغرض

تحدد هذه الوثيقة طريقة تنفيذ اختبار قبول المستخدم (UAT)، وتوثيق نتائج الاختبار، وتجهيز دليل الاستخدام والأسئلة الشائعة وتدقيق المحتوى قبل الإصدار.

تركز Stage A على إعداد الخطة والسيناريوهات وقوالب التسجيل. ولا تمثل نتائج UAT فعلية، ولا تستبدل الاختبارات التقنية أو الأمنية أو اختبارات الانحدار.

## 2. نطاق C-05

تتحقق C-05 من أن المستخدم النهائي يستطيع فهم الرحلات الأساسية وتنفيذها، وأن النصوص الظاهرة متسقة مع C-03 وC-04 والواجهات الفعلية.

تشمل المهمة:

- خطة UAT وسيناريوهات الطالب.
- سيناريوهات المدير عند دخول لوحة الإدارة ضمن الإصدار.
- تسجيل PASS وFAIL والنتيجة الفعلية والدليل.
- إنشاء أو ربط Issues عند وجود عيوب فعلية.
- إعادة اختبار السيناريوهات بعد الإصلاح.
- إعداد دليل الاستخدام وFAQ.
- تدقيق النصوص والمصطلحات والمصادر.
- تجهيز Evidence لتسليمها إلى H-05.

لا تشمل المهمة إصلاح Backend أو Frontend، ولا System Testing أو Regression Testing أو Security Testing أو إنشاء Release Tag.

## 4. مراحل التنفيذ

### Stage A — إعداد الخطة والمحتوى

تنفذ قبل اكتمال الواجهات، وتشمل:

1. اعتماد هذه الخطة.
2. اعتماد سيناريوهات الطالب والمدير.
3. تحديد Expected Result لكل سيناريو.
4. تجهيز قالب تسجيل UAT.
5. تجهيز هيكل دليل الاستخدام.
6. تجهيز FAQ الأولية.
7. تجهيز قائمة تدقيق المحتوى.
8. توحيد المصطلحات مع C-03 وC-04 وF-04 وF-05.

### Stage B — UAT بعد استقرار الواجهات

تنفذ بعد استقرار F-04 وF-05 وB-05، وتشمل:

1. تنفيذ السيناريوهات مع طالب أو ممثل مناسب.
2. تنفيذ سيناريوهات المدير عند دخولها في الإصدار.
3. تسجيل النتيجة الفعلية والدليل.
4. إنشاء Issues للعيوب الحقيقية.
5. إعادة الاختبار بعد الإصلاح.
6. تحديث دليل الاستخدام من الواجهة النهائية.
7. تحديث FAQ وتدقيق كل النصوص.
8. تجهيز Evidence النهائية وتسليمها إلى H-05.

## 5. قواعد تنفيذ UAT

- لا يشرح المختبر للمستخدم خطوات يفترض أن يفهمها من النظام.
- لا يعدل Expected Result بعد ظهور النتيجة لتبرير PASS.
- يسجل كل Failure حقيقي.
- تفصل الملاحظة التحسينية عن العيب التقني.
- يربط كل Failure فعلي بـIssue مناسب.
- يعاد اختبار السيناريو بعد إصلاح العيب.
- تسجل نسخة التطبيق ونسخة التقييم وتاريخ الاختبار.
- لا تستخدم نتيجة طالب حقيقية في التوثيق دون إخفاء البيانات الحساسة والموافقة المناسبة.

## 6. معايير PASS وFAIL

يسجل السيناريو **PASS** عندما يحقق النظام النتيجة المتوقعة دون مساعدة تؤثر في هدف الاختبار، ولا يظهر عيب يمنع إتمام الرحلة أو يغير معناها.

يسجل السيناريو **FAIL** عندما لا يستطيع المستخدم إتمام الرحلة، أو يفهمها بطريقة تخالف الهدف، أو تظهر رسالة مضللة، أو يفشل النظام في حفظ النتيجة أو عرضها، أو يظهر عيب مؤثر في الاستخدام.

تسجل الملاحظة التحسينية منفصلة عن FAIL إذا كانت الرحلة مفهومة وقابلة للإتمام، لكن يمكن تحسين وضوحها أو سرعتها أو شكلها.

## 7. سيناريوهات الطالب

### STU-01 — فهم الصفحة الرئيسية

**Preconditions:** فتح النظام دون تسجيل دخول.
**Steps:** اقرأ عنوان الصفحة ووصف المنصة وحدد الغرض من النظام.
**Expected Result:** يفهم المستخدم أن المنصة تساعد على استكشاف الميول والتخصصات، ولا تقدم قرارًا نهائيًا.

### STU-02 — إنشاء الحساب وتسجيل الدخول

**Preconditions:** لا يوجد حساب مستخدم تجريبي مسجل الدخول.
**Steps:** أنشئ حسابًا تجريبيًا ثم سجل الدخول.
**Expected Result:** ينجح إنشاء الحساب وتسجيل الدخول، وتظهر لوحة الطالب دون كشف تفاصيل داخلية.

### STU-03 — بدء التقييم

**Preconditions:** مستخدم طالب مسجل الدخول ونسخة تقييم منشورة.
**Steps:** افتح التقييم واضغط بدء التقييم.
**Expected Result:** تبدأ جلسة واحدة مرتبطة بنسخة التقييم المنشورة، وتظهر التعليمات قبل المواقف.

### STU-04 — فهم تعليمات التقييم

**Preconditions:** فتح صفحة مقدمة التقييم.
**Steps:** اقرأ المقدمة وطريقة الإجابة وخياري عدم التمثيل وعدم القدرة على الحكم.
**Expected Result:** يفهم المستخدم أن التقييم استكشافي، وأنه يختار حالة إجابة واحدة لكل موقف.

### STU-05 — الإجابة والتنقل

**Preconditions:** جلسة تقييم قيد التنفيذ.
**Steps:** اختر إجابة أساسية، أضف تقييمًا اختياريًا عند الحاجة، احفظ وانتقل ثم عد إلى موقف سابق.
**Expected Result:** تحفظ الإجابة، ويستطيع المستخدم التنقل وتعديل الإجابة ما دامت الجلسة غير مكتملة.

### STU-06 — استخدام الخيارات الخاصة

**Preconditions:** عرض موقف تقييم.
**Steps:** جرّب `لا يشبهني أي من هذه التصرفات` و`لا أستطيع الحكم على هذا الموقف`.
**Expected Result:** يقبل النظام حالة واحدة فقط، ولا يعرض التقييمات الاختيارية مع أي من الخيارين الخاصين.

### STU-07 — الحفظ والاستئناف

**Preconditions:** وجود جلسة غير مكتملة مع إجابات محفوظة.
**Steps:** غادر التقييم ثم سجل الدخول مجددًا وافتحه.
**Expected Result:** يستعيد النظام الجلسة الحالية والتقدم والإجابات المحفوظة بدل إنشاء جلسة جديدة.

### STU-08 — إكمال التقييم

**Preconditions:** معالجة المواقف المطلوبة وفق شروط الإكمال.
**Steps:** راجع الإجابات واضغط إكمال التقييم.
**Expected Result:** تظهر رسالة الإكمال، وتحفظ النتيجة، ولا يمكن تعديل الجلسة المكتملة.

### STU-09 — فهم النتيجة

**Preconditions:** وجود نتيجة محفوظة.
**Steps:** افتح النتيجة واقرأ العنوان والوصف والمجالات الأعلى والتنبيه التوضيحي.
**Expected Result:** يفهم المستخدم أن النتيجة إرشادية وتعكس ميولًا حالية، وليست نسبة نجاح أو حكمًا نهائيًا.

### STU-10 — فهم مجالات RIASEC

**Preconditions:** فتح صفحة النتيجة.
**Steps:** اقرأ وصف المجالات الظاهرة.
**Expected Result:** يفهم المستخدم المجالات بوصفها أنشطة أو اهتمامات، لا صفات شخصية ثابتة أو تشخيصًا.

### STU-11 — فهم التوصيات

**Preconditions:** نتيجة تحتوي على تخصصات مقترحة.
**Steps:** اقرأ سبب التقارب والتنبيه المصاحب للتوصيات.
**Expected Result:** يفهم المستخدم أن التخصصات خيارات للاستكشاف وليست قرارًا نهائيًا أو ضمانًا للنجاح.

### STU-12 — فتح تخصص مقترح

**Preconditions:** ظهور تخصص مقترح في النتيجة.
**Steps:** افتح بطاقة التخصص واقرأ الوصف والأنشطة والمهارات والمصادر.
**Expected Result:** يفتح وصف التخصص ومصادره دون تسجيل توصية قطعية أو نسبة نجاح.

### STU-13 — فتح الملف الشخصي

**Preconditions:** مستخدم طالب مسجل الدخول.
**Steps:** افتح Profile واقرأ البيانات والروابط المتاحة.
**Expected Result:** يفهم المستخدم معلومات ملفه ويصل إلى وظائفه دون أزرار أو مصطلحات مربكة.

### STU-14 — فتح نتيجة تاريخية

**Preconditions:** وجود نتيجتين محفوظتين أو نتيجة تاريخية متاحة للاختبار.
**Steps:** افتح سجل النتائج ثم نتيجة سابقة.
**Expected Result:** تعرض النتيجة بإصدارها الأصلي دون إعادة حسابها تلقائيًا وفق إصدار أحدث.

## 8. سيناريوهات المدير عند دخول الإدارة في الإصدار

تُنفذ هذه السيناريوهات فقط إذا كانت لوحة الإدارة ضمن نطاق الإصدار الحالي. وإذا لم تكن ضمن الإصدار، تُسجل السيناريوهات بوصفها مؤجلة إلى مرحلة دخول الإدارة في النطاق، ولا تُحسب نتائجها ضمن UAT الحالي.

### ADM-01 — فهم لوحة التحكم

**Preconditions:** وجود حساب مدير تجريبي وتسجيل الدخول إلى النظام.
**Steps:** افتح لوحة التحكم، واقرأ أسماء الأقسام والبطاقات والرسائل، وحدد الوظيفة الأساسية لكل قسم.
**Expected Result:** يفهم المدير الأقسام الأساسية، ويستطيع تحديد مكان إدارة التقييمات والأسئلة والإحصاءات دون أزرار أو مصطلحات مربكة.

### ADM-02 — الوصول إلى إصدارات التقييم

**Preconditions:** تسجيل الدخول بحساب مدير، ووجود صفحة إصدارات التقييم.
**Steps:** افتح صفحة إصدارات التقييم، واعرض قائمة الإصدارات المتاحة.
**Expected Result:** يستطيع المدير الوصول إلى الإصدارات وقراءة حالتها ونسختها دون ظهور تفاصيل تقنية غير لازمة.

### ADM-03 — فهم حالات Draft وPublished

**Preconditions:** وجود إصدار مسودة وإصدار منشور في قائمة الإصدارات.
**Steps:** افتح تفاصيل الإصدارين وقارن بين حالتي Draft وPublished.
**Expected Result:** يميز المدير بوضوح بين المسودة والمنشور، ويفهم أن التعديل والنشر يخضعان لقواعد مختلفة.

### ADM-04 — إدارة أسئلة المسودة

**Preconditions:** وجود إصدار بحالة Draft وصلاحية المدير لإدارة أسئلته.
**Steps:** افتح المسودة، أضف أو عدّل سؤالًا وفق القواعد المعتمدة، ثم احفظ التغيير.
**Expected Result:** يستطيع المدير تعديل المسودة وحفظها، وتظهر رسالة نجاح واضحة أو رسالة رفض تشرح الإجراء المطلوب عند وجود خطأ.

### ADM-05 — تنفيذ Publish

**Preconditions:** وجود مسودة مكتملة ومستوفية لشروط النشر.
**Steps:** راجع المسودة، نفذ إجراء Publish، ثم تحقق من الحالة الجديدة.
**Expected Result:** ينشر النظام المسودة المستوفية للشروط، ويعرض رسالة نجاح وحالة Published واضحة. وإذا لم تستوفِ المسودة الشروط، يرفض النظام النشر برسالة مفهومة.

### ADM-06 — فهم Statistics

**Preconditions:** وجود بيانات إحصائية تجريبية وصلاحية المدير للوصول إلى صفحة الإحصاءات.
**Steps:** افتح صفحة الإحصاءات، واقرأ المؤشرات والفلاتر المتاحة، وحدد معنى كل مؤشر ظاهر.
**Expected Result:** يفهم المدير مؤشرات الجلسات والإكمال والنتائج المعروضة، ولا تظهر بيانات شخصية لطالب بعينه ضمن الإحصاءات العامة.

### ADM-07 — فهم رسائل الرفض والأخطاء

**Preconditions:** وجود حالة تجريبية تؤدي إلى رفض إجراء أو ظهور رسالة خطأ.
**Steps:** نفذ الإجراء غير المسموح أو افتح الحالة التي تتطلب معالجة، ثم اقرأ الرسالة الظاهرة.
**Expected Result:** يفهم المدير سبب الرفض أو الخطأ والخطوة المطلوبة لمعالجته، دون ظهور تفاصيل برمجية داخلية غير مناسبة للمستخدم.

## 10. متطلبات الدليل والـFAQ

### هيكل دليل الاستخدام

يجب أن يغطي الدليل النهائي، اعتمادًا على الواجهة الفعلية:

1. الدخول إلى النظام.
2. إنشاء الحساب.
3. لوحة الطالب.
4. بدء التقييم.
5. الإجابة والحفظ.
6. الاستئناف.
7. إكمال التقييم.
8. فهم النتيجة.
9. فهم المجالات الستة.
10. فهم التوصيات.
11. دليل التخصصات.
12. الملف الشخصي.
13. سجل النتائج.
14. الرسائل والحالات المهمة.

لا يشرح الدليل وظائف غير موجودة، ولا يصف خطوات تختلف عن الواجهة النهائية.

### FAQ الأولية

- ما هدف التقييم؟
- هل النتيجة تحدد تخصصي؟
- هل أستطيع العودة إلى التقييم؟
- ماذا تعني المجالات الأعلى؟
- لماذا تظهر عدة تخصصات؟
- هل النتيجة نهائية؟
- أين أجد نتائجي السابقة؟
- ماذا أفعل إذا لم أفهم موقفًا؟
- ما الفرق بين عدم التمثيل وعدم القدرة على الحكم؟
- كيف أستخدم النتيجة مع الأسرة أو المرشد؟

## 12. التعامل مع العيوب

عند اكتشاف Failure حقيقي:

1. سجل السيناريو المتأثر.
2. اكتب Expected Result وActual Result بوضوح.
3. أرفق Screenshot أو دليلًا مناسبًا دون بيانات حساسة.
4. أنشئ Issue أو اربط Issue موجودًا.
5. أحل العيب إلى صاحب المجال المناسب.
6. لا تصلح C-05 العيب بدل صاحبه.
7. بعد الإصلاح أعد تنفيذ السيناريو.
8. حدّث حالة الاختبار والـEvidence.
