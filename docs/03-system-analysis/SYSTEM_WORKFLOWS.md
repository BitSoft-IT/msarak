# المرحلة الرابعة — مسارات عمل النظام

**الملف:** `SYSTEM_WORKFLOWS.md`  
**الحالة:** مرشح للاعتماد  
**النطاق:** سلوك النظام فقط؛ دون تصميم واجهات أو قاعدة بيانات أو API.

## 1. قرارات المرحلة

- الاختبار المعتمد: **18 موقفًا**.
- أدوار النظام: زائر، طالب مسجل، مدير.
- ولي الأمر والمرشد خارج النظام.
- دليل التخصصات ثابت في النسخة الأولى، ولا يديره المدير.
- المدير يدير نماذج الأسئلة والأوزان والإحصائيات.
- النتيجة توجيهية، محفوظة، وغير قابلة للتعديل اليدوي.
- كل جلسة ترتبط بإصدار ثابت من نموذج التقييم.
- لا إشعارات، ولا تفعيل بريد، ولا حذف نتائج في النسخة الأولى.

## 2. توزيع المسؤوليات

| الطبقة | المسؤولية |
|---|---|
| الواجهة | العرض، الإدخال، التحقق الشكلي، وإظهار الحالات |
| الخادم | المصادقة، الصلاحيات، قواعد العمل، الحساب، والحفظ |
| قاعدة البيانات | الحسابات، إصدارات التقييم، الجلسات، الإجابات، النتائج، والإحصائيات |
| المحتوى الثابت | دليل التخصصات ومصادره المعتمدة |
| خدمة البريد | إرسال رابط استعادة كلمة المرور فقط |

## 3. حالات جلسة التقييم

| الحالة | معناها | الانتقال المسموح |
|---|---|---|
| لا توجد جلسة | لم يبدأ الطالب | بدء جلسة |
| غير مكتملة | بدأت ولم تُنهَ | حفظ إجابة، استئناف، إكمال |
| مكتملة | حُسبت وحُفظت النتيجة | عرض النتيجة أو بدء جلسة جديدة |

- لا ينشئ النظام أكثر من جلسة غير مكتملة للطالب في الإصدار نفسه.
- عند العودة، تُستأنف الجلسة القائمة.
- الإجابة المعتمدة: أقرب + أقل مختلفان، أو «لا أستطيع الحكم».
- يجب التعامل مع جميع المواقف الـ18.
- لا تُحسب النتيجة إذا كانت الإجابات المحتسبة أقل من 15.

## 4. المسارات

### WF-01 — تصفح دليل التخصصات

**الممثل:** الزائر أو الطالب  
**البداية:** فتح دليل التخصصات.

1. تعرض الواجهة التخصصات العشرة.
2. يختار المستخدم تخصصًا.
3. تعرض الصفحة محتواه ومصادره وتاريخ تحديثه.
4. يفتح الرابط الخارجي في صفحة مستقلة.

**النجاح:** فهم التخصص دون تسجيل.  
**الاستثناء:** عند نقص قسم، يظهر أنه غير متاح بدل اختلاق محتوى.

### WF-02 — مقارنة تخصصين

**الممثل:** الزائر أو الطالب  
**البداية:** اختيار المقارنة.

1. يحدد المستخدم تخصصين مختلفين.
2. يعرض النظام الحقول المشتركة بالترتيب نفسه.
3. يوضح الحقول الناقصة لكل تخصص.

**النجاح:** مقارنة عادلة وقابلة للقراءة.  
**الاستثناء:** لا تبدأ المقارنة قبل اختيار تخصصين مختلفين.

### WF-03 — إنشاء الحساب والدخول

**الممثل:** الزائر أو الطالب

1. يسجل الزائر بريدًا صالحًا وكلمة مرور.
2. يتحقق الخادم من عدم تكرار البريد وينشئ الحساب دون تفعيل.
3. يسجل الطالب الدخول أو الخروج.
4. يحمي الخادم أداة التقييم والنتائج من غير المسجلين.

**الأخطاء:** بريد مكرر، بيانات غير صحيحة، طلب غير مصرح.  
**النجاح:** جلسة دخول آمنة دون كشف سبب حساس في رسالة الخطأ.

### WF-04 — استعادة كلمة المرور

**الممثل:** الطالب، خدمة البريد

1. يرسل الطالب بريده.
2. يعرض النظام رسالة موحدة سواء وُجد الحساب أم لا.
3. عند وجوده، يرسل رابطًا صالحًا لمدة لا تتجاوز ساعة.
4. يعيّن الطالب كلمة جديدة.
5. يبطل الرابط بعد الاستخدام أو انتهاء المدة.

**النجاح:** استعادة آمنة دون كشف الحسابات المسجلة.

### WF-05 — بدء التقييم أو استئنافه

**الممثل:** الطالب المسجل

1. يتحقق الخادم من وجود جلسة غير مكتملة.
2. إن وُجدت، يستعيد إصدار النموذج والإجابات والتقدم.
3. وإلا ينشئ جلسة مرتبطة بإصدار النموذج المنشور حاليًا.
4. تعرض الواجهة التعليمات ثم المواقف واحدًا واحدًا.

**النجاح:** جلسة واحدة متسقة لا تتغير بتعديل نموذج لاحق.  
**الخطأ:** إذا لم يوجد نموذج منشور، لا يبدأ الاختبار وتظهر رسالة واضحة.

### WF-06 — تسجيل الإجابة

**الممثل:** الطالب المسجل

1. يختار الطالب الأقرب والأقل، أو تعذر الحكم.
2. تتحقق الواجهة من اختلاف الخيارين.
3. يعيد الخادم التحقق من السؤال والخيارات والإصدار والملكية.
4. تحفظ الإجابة كعملية واحدة، ويمكن استبدالها قبل الإكمال.
5. تؤكد الواجهة الحفظ ثم تنتقل.

**الخطأ:** عند فشل الشبكة تبقى الإجابة ظاهرة ويُعاد الإرسال دون إنشاء تكرار.  
**النجاح:** لا تُفقد إجابة أكد النظام حفظها.

### WF-07 — إكمال التقييم وإنتاج النتيجة

**الممثل:** الطالب المسجل  
**الشرط:** معالجة المواقف الـ18 ووجود 15 إجابة محتسبة على الأقل.

1. يطلب الطالب الإكمال.
2. يتحقق الخادم مرة أخيرة من الجلسة والإجابات.
3. يحسب درجات RIASEC بالنموذج المعتمد.
4. يرتب المجالات ويحتفظ بالتعادل.
5. يقارن الملف بملفات التخصصات المعتمدة.
6. يحفظ الدرجات والتوصيات وإصدارات النموذج والمطابقة.
7. يحول الجلسة إلى مكتملة ويعيد النتيجة.

**الضمان:** الإكمال والحساب والحفظ عملية واحدة؛ لا توجد جلسة مكتملة بلا نتيجة.  
**الخطأ:** عند نقص الإجابات يعود الطالب إلى المواقف غير المعالجة.

### WF-08 — عرض النتيجة والاستكشاف

**الممثل:** الطالب المسجل

1. يعرض النظام أعلى ثلاثة مجالات ووصفها النشاطي.
2. يعرض 3–5 تخصصات للاستكشاف مع سبب التقارب.
3. يوضح أن النتيجة ليست نسبة نجاح أو قرارًا نهائيًا.
4. يعرض القيم والخبرة والعوائق منفصلة إن جُمعت.
5. ينتقل الطالب إلى صفحة أي تخصص مقترح.

**النجاح:** نتيجة مفهومة تقود إلى الاستكشاف، لا إلى حكم قطعي.

### WF-09 — سجل النتائج

**الممثل:** الطالب المسجل

1. يطلب الطالب نتائجه.
2. يعرض الخادم النتائج التي يملكها فقط، من الأحدث إلى الأقدم.
3. يفتح الطالب نتيجة محفوظة بإصداراتها الأصلية.

**الضمان:** لا يعاد حساب نتيجة تاريخية تلقائيًا عند تغير نموذج لاحق.

### WF-10 — إدارة نموذج التقييم

**الممثل:** المدير

1. ينشئ المدير مسودة من نموذج قائم أو جديد.
2. يعدل الأسئلة والخيارات والرموز والأوزان داخل المسودة.
3. يتحقق النظام من اكتمال المواقف والخيارات وتوازن المجالات.
4. ينشر المدير إصدارًا جديدًا بعد اجتياز التحقق.
5. تستخدم الجلسات الجديدة الإصدار الجديد فقط.

**محظور:** تعديل إصدار منشور، أو نتيجة طالب، أو جلسة بدأت.  
**الخطأ:** ترفض المسودة غير المكتملة أو غير المتوازنة عند النشر.

### WF-11 — عرض الإحصائيات

**الممثل:** المدير

1. يحدد النظام الفترة المطلوبة.
2. يحسب الاختبارات التي بدأت والمكتملة ونسبة الإكمال.
3. يعرض أكثر التخصصات ظهورًا في النتائج.
4. لا يعرض إجابات طالب بعينه ضمن الإحصائيات العامة.

## 5. قواعد مشتركة

- كل عملية محمية تتحقق من الهوية والملكية والصلاحية على الخادم.
- رسائل الخطأ مفهومة ولا تكشف تفاصيل داخلية.
- المحتوى الخارجي يعرض كرابط ومصدر، ولا يعد جزءًا من النظام.
- النتيجة المحفوظة غير قابلة للتعديل اليدوي.
- دليل التخصصات يُحدّث عبر إصدار المحتوى، لا عبر لوحة المدير.
- أي تغيير في نموذج التقييم ينشئ إصدارًا جديدًا.
- لا ينتقل التحليل هنا إلى تصميم الجداول أو المسارات البرمجية.

## 6. معايير إغلاق الوثيقة

- كل متطلب وظيفي له مسار واضح.
- لكل مسار بداية ونجاح وأخطاء وحالة نهائية.
- لا توجد وظيفة خارج نطاق النسخة الأولى.
- لا يوجد تعارض مع نموذج الأسئلة المعتمد.
- القرارات التقنية التفصيلية مؤجلة لمرحلتها.
