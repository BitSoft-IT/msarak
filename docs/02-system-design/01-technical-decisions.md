# القرارات التقنية المعتمدة

**المشروع:** مسارك — منصة التوجيه الأكاديمي والمهني لطلاب الثانوية  
**الحالة:** معتمد للتنفيذ  
**آخر تحديث:** 2026-09-11

## 1. الغرض من الملف

هذا الملف هو المرجع النهائي للتقنيات المستخدمة في النسخة الأولى. لا يختار عضو الفريق بديلًا مختلفًا أثناء التنفيذ إلا بعد تسجيل قرار جديد ومراجعته.

المبدأ الحاكم: **نستخدم أقل بنية تحقق المتطلبات بوضوح، ونتجنب إضافة تقنية لا يحتاجها المشروع الآن.**

---

## 2. البيئة المعتمدة

| المكوّن | القرار المعتمد | ملاحظة |
|---|---|---|
| PHP | `8.2.12` | الإصدار الموجود والمستخدم فعليًا في بيئة التأسيس. |
| Laravel | `12.x` | أُنشئ المشروع على سلسلة Laravel 12؛ رقم التحديث الدقيق يحدده `composer.lock`. |
| Composer | `2.9.5` | لإدارة حزم PHP. |
| Node.js | `24.13.1` | لبناء ملفات الواجهة. |
| npm | `11.8.0` | لإدارة حزم الواجهة. |
| Git | `2.50.1.windows.1` | لإدارة الإصدارات. |
| قاعدة البيانات | MySQL | تستخدم محليًا وفي التشغيل؛ لا نعتمد SQLite. |
| بيئة الجهاز | Windows + XAMPP | PHP وخدمة قاعدة البيانات المحليتان تعملان من البيئة الحالية. |

هذه الأرقام توثق بيئة التأسيس، بينما يحدد `composer.lock` و`package-lock.json` نسخ مكتبات المشروع التي يجب أن يستخدمها الفريق.

## 3. المكدس التقني

| الجزء | التقنية | سبب الاختيار |
|---|---|---|
| تطبيق الخادم | Laravel 12.x | مناسب لتطبيق ويب واحد ويقدم Routing وValidation وSessions وCSRF وEloquent والاختبارات ضمن إطار واحد. |
| لغة الخادم | PHP 8.2.12 | متوافقة مع Laravel 12 وموجودة فعليًا في البيئة المعتمدة. |
| صفحات الواجهة | Blade | تبقي الواجهة والخادم في تطبيق واحد دون تعقيد SPA. |
| التنسيق | Tailwind CSS | لبناء واجهة متجاوبة ومنظمة على الهاتف والحاسوب. |
| التفاعل | JavaScript + Fetch API | لحفظ الإجابات وتنفيذ العمليات الجزئية دون إعادة تحميل الصفحة كاملة. |
| البيانات التشغيلية | MySQL + Eloquent | لحفظ المستخدمين وإصدارات التقييم والأسئلة والجلسات والإجابات والنتائج. |
| المحتوى الثابت | JSON داخل `resources/data/` | دليل التخصصات ثابت في النسخة الأولى ولا يحتاج جدولًا أو لوحة CRUD. |
| الاختبارات | PHPUnit عبر Laravel | لاختبار المنطق والمسارات والصلاحيات وتدفقات النظام. |
| إدارة العمل | Git + GitHub | لإدارة Issues والفروع وPull Requests والمراجعة والدمج. |

## 4. شكل التطبيق

النظام **تطبيق Laravel واحد** وليس Frontend وBackend منفصلين:

- صفحات العرض تعاد باستخدام Blade.
- المسارات توضع في `routes/web.php`.
- Fetch يرسل ويستقبل JSON داخل التطبيق نفسه عند حفظ الإجابات أو تنفيذ عمليات المدير.
- لا توجد API عامة في النسخة الأولى.
- لا نستخدم React أو Vue أو تطبيق SPA.
- لا نستخدم Microservices.

إذا احتاج المشروع مستقبلًا تطبيق هاتف أو تكاملًا خارجيًا، يُتخذ قرار مستقل بشأن API قبل تنفيذه.

---

## 5. المصادقة والجلسات

القرار المعتمد:

- مصادقة تعتمد على Laravel Session وCookies.
- حماية الطلبات المتغيرة بـCSRF.
- حماية المسارات باستخدام `auth` والأدوار المناسبة.
- التحقق من ملكية جلسة التقييم والنتيجة باستخدام Policies.
- استخدام أدوات Laravel الأساسية لتنفيذ التسجيل والدخول والخروج والاستعادة.

غير معتمد في النسخة الأولى:

- Laravel Sanctum.
- JWT.
- API Tokens.
- Laravel Breeze أو أي Starter Kit باعتباره اعتمادًا إلزاميًا.

سبب ذلك أن النظام تطبيق Blade واحد، ولا يحتاج طبقة مصادقة API أو حزمة واجهات جاهزة إضافية.

## 6. قاعدة البيانات

### البيانات المخزنة في MySQL

- المستخدمون والأدوار.
- إصدارات التقييم.
- الأسئلة الثمانية عشر وخياراتها الأربعة.
- جلسات التقييم والإجابات.
- النتائج ودرجات RIASEC.
- التوصيات المحفوظة مع النتيجة.

### القرار البيئي

- `DB_CONNECTION=mysql` في بيئة التطوير والتشغيل.
- لا ننشئ `database/database.sqlite`.
- لا نكتب تعليمات منفصلة لـSQLite.
- ملف `.env` محلي ولا يرفع إلى GitHub.
- تضاف أسماء المتغيرات اللازمة فقط إلى `.env.example` دون أسرار.

استخدام قاعدة واحدة يقلل اختلاف السلوك بين أعضاء الفريق وبيئة التشغيل، خصوصًا في القيود وTransactions وقفل الصفوف.

---

## 7. نموذج التقييم

- نموذج القياس المعتمد في النسخة الأولى هو RIASEC.
- عدد الأسئلة المعتمد: **18 سؤالًا**.
- لكل سؤال **4 خيارات** وفق النموذج المعتمد.
- الأسئلة والخيارات والأوزان تحفظ في MySQL ضمن إصدار تقييم.
- حساب الدرجات يتم على الخادم داخل `ScoringService`.
- المطابقة مع التخصصات تتم على الخادم داخل `RecommendationService`.
- لا ترسل رموز الأوزان أو منطق الحساب الحساس إلى المتصفح.
- تحفظ النتيجة ودرجاتها والتوصيات حتى يمكن الرجوع إليها دون إعادة حسابها من بيانات متغيرة.

---

## 8. دليل التخصصات

القرار المعتمد:

- الملف: `resources/data/specializations.json`.
- يحتوي على التخصصات العشرة وبنيتها ومصادرها وملفات RIASEC الخاصة بها.
- يقرأه `SpecializationCatalogService` على الخادم.
- تستخدمه صفحات الدليل والمقارنة وخدمة التوصية.
- لا ينشأ جدول `specializations`.
- لا توجد عمليات إضافة أو تعديل أو حذف للتخصصات من لوحة المدير في النسخة الأولى.
- تحديث المحتوى يتم بمراجعة الملف داخل GitHub مثل أي تغيير في المشروع.

وجود JSON ثابت لا يعني أن المتصفح ينفذ المطابقة؛ المصدر ثابت، لكن القراءة والتحقق والمطابقة مسؤولية الخادم.

## 9. توزيع المسؤوليات البرمجية

| الطبقة | مسؤوليتها |
|---|---|
| Routes | ربط الطلب بالـController المناسب. |
| Middleware | التحقق من الدخول والدور. |
| Form Requests | التحقق من صحة البيانات المرسلة. |
| Policies | التحقق من الملكية والصلاحية. |
| Controllers | توجيه الطلب وإرجاع View أو JSON دون منطق أعمال ثقيل. |
| Services | تنفيذ قواعد العمل والحساب والمطابقة والعمليات المركبة. |
| Models | تمثيل جداول MySQL وعلاقاتها. |
| Blade | عرض الصفحات والنتائج. |
| JavaScript | تفاعل الواجهة وإرسال طلبات Fetch فقط، دون تنفيذ الحساب الحساس. |

## 10. الأمان والجودة

- تستخدم كلمات المرور عبر Laravel `Hash` ولا تخزن كنص واضح.
- تستخدم Eloquent أو Query Builder مع معاملات آمنة؛ أي SQL خام يحتاج سببًا ومراجعة.
- تطبق Validation على جميع المدخلات.
- تستخدم Blade escaping الافتراضية عند عرض النصوص.
- تمنع Policies وصول الطالب إلى جلسة أو نتيجة لا يملكها.
- تنفذ عمليات الإكمال والنشر المركبة داخل Transactions.
- تطبق Rate Limiting على محاولات الدخول والعمليات الحساسة المناسبة.
- لا ترفع كلمات المرور أو المفاتيح أو `.env` إلى GitHub.
- يضاف اختبار مناسب عند تغيير المنطق أو الصلاحيات أو البيانات.

## 11. ما لن نستخدمه الآن

| التقنية أو الفكرة | القرار |
|---|---|
| SQLite | غير معتمدة. |
| Laravel Breeze | غير معتمد كStarter Kit للمشروع الحالي. |
| Sanctum أو JWT | غير مطلوبين لعدم وجود API عامة. |
| Axios | غير مطلوب؛ Fetch API تكفي. |
| React أو Vue | غير مطلوبين؛ Blade تحقق الحاجة. |
| جدول تخصصات | غير مطلوب؛ المصدر JSON ثابت. |
| CRUD للتخصصات | خارج نطاق النسخة الأولى. |
| حساب RIASEC في JavaScript | ممنوع؛ الحساب على الخادم. |
| فرع `develop` | غير معتمد؛ إدارة الفروع موثقة في دليل GitHub. |
